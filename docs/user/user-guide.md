# Customer guide — prepare a custom website brief

> Status: Draft guide, pending HTS review. Owner: HTS team. Historical frontend baseline: 2026-10-02. Current edition: Unreleased.

The HTS site helps you describe a custom website before discussing a proposal. You do not need an account. Start from a service card, a project in "Ideas in action" or the brief section. The projects shown there are live sites running on HTS servers; each card links to the site.

## Answer the wizard

1. **Contact and project:** identify yourself and your business, choose the service/site type and indicate whether the project is new or already exists. An existing website URL is optional.
2. **Goals and scope:** describe what the site should achieve, who will use it and which pages/features you need.
3. **Visual direction:** choose a preferred style, describe colors, provide up to five HTTP/HTTPS reference addresses and explain which brand/content materials are available. Select desired site languages. This asks about assets; it does not upload them.
4. **Planning:** explain integrations, domain/hosting needs, approximate budget and timing. If uncertain, use the available uncertainty choice or explain your situation. These preferences are not a fixed quote or promised delivery date.
5. **Review and download:** check every answer, use edit controls to correct a stage and download the UTF-8 text brief.

Next checks the current step. Back preserves answers in the current session. Do not include passwords, hosting credentials, API keys or payment details. Contact/project information must be treated as personal information when you share the downloaded file.

## What happens after downloading

The file is saved on your device. **It is not automatically sent to HTS.** Keep your copy and contact the team using a verified channel you already have. Do not assume that the website has accepted a request or reserved a project date. Reloading, changing session or a server restart can discard the in-memory draft.

The header switches between PT-BR, EN and ES and between light/black themes. Preferences may persist, but that does not persist your answers. See [FAQ](faq.md) and [troubleshooting](troubleshooting.md).
